# 利用状況の計測（Cloudflare Web Analytics）

「どのくらい使われているか」を知るための設定です。**2026年10月24日に有効化しました**（`app/js/analytics.js` の `ANALYTICS_TOKEN` にトークンが入っています）。プライバシーポリシー（`about.html`）と `README.md` の文言も、下の内容に差しかえ済みです。

## 何が分かるか／分からないか

Cookieを使わず、個人を特定しない集計です。分かるのは、ページの表示回数、訪問数、国、端末・ブラウザの種類、どこから来たか（検索・X・直接）、表示の速さ、です。

分からないのは、「何問解いたか」「どの問題を間違えたか」のような、アプリの中での動きです。これは、記録が端末の中だけにあるという約束（プライバシーポリシー）を保つために、あえて取っていません。

## 有効にした手順（記録）

Cloudflareが自動で埋め込む方式は、`app/_headers` の `Cache-Control: no-transform` で意図的に止めてあります。そのため、トークンを使う方式にします。

1. Cloudflareのダッシュボードで **Web Analytics** を開き、「サイトを追加」する。ホスト名は `unko-drill.pages.dev`。
2. 追加の方法で、自動ではなく **JavaScriptスニペットを自分で貼る方式** を選ぶ。
3. 表示されるスニペットの `data-cf-beacon='{"token": "…"}'` の、32文字の英数字（`…` の部分）をコピーする。
4. そのトークンを `app/js/analytics.js` の `ANALYTICS_TOKEN` に入れる。
5. `app/about.html` のプライバシーポリシーと `README.md` の記述を、下の文言に差しかえる。
6. `node --test tests/*.test.mjs` を実行する（トークンを入れたのに記述を直していないと、テストが落ちます）。
7. mainにマージして公開する。

トークンは、ページのソースに誰でも見える形で載る値で、秘密ではありません。画面の名前はCloudflare側で変わることがあります。

ブラウザの「トラッキング拒否（Do Not Track）」や「Global Privacy Control」がオンのときは、計測用のスクリプトを読み込みません。

## `about.html` のプライバシーポリシーに入れた文言

「アクセス解析・Cookie」の見出しの下の段落を、次の文に差しかえます。

> 本サイトは、利用状況（ページの表示回数、訪問数、国、端末やブラウザの種類、アクセス元のサイトなど）を知るために、Cloudflare, Inc. の「Cloudflare Web Analytics」を使っています。Cookieは使わず、個人を特定する情報や、解いた問題の内容・成績は送信しません。ブラウザの「トラッキング拒否」の設定がオンのときは、読み込みません。取り扱いは、Cloudflareのプライバシーポリシーに従います。広告配信のためのCookieは使っていません。

「外部サイトへのリンク」の段落の最後の「本サイトは、ボタンを押すまで、これらのサイトとは通信しません。」は、そのままで正しいままです（Cloudflareへの通信は、ページを開いたときに行われるため、上の段落に分けて書いています）。

## `README.md` に入れた文言

特徴の「記録はすべて端末内（localStorage）に保存し、外部には送信しません」の後ろに、次を足します。

> 利用状況の把握のために、Cookieを使わない集計ツール（Cloudflare Web Analytics）を使っています。解いた問題や成績は送信しません。

## やめるとき

`ANALYTICS_TOKEN` を空に戻し、`about.html` と `README.md` の文言を元に戻します（元の文言は、このリポジトリの履歴にあります）。テストが、食い違いを見つけます。
